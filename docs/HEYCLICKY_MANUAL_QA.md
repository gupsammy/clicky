# HeyClicky parity manual QA

This is the acceptance plan for Clicky's clean-room HeyClicky parity work. It complements automated tests by requiring a person to observe the real macOS behavior in Xcode-run builds. Every run records the app commit, macOS version, display layout, Codex version, transcription provider, permission state, and whether the behavior was compared with the installed HeyClicky reference.

The status vocabulary is intentionally strict: `Verified` means the behavior was observed in the native app; `Automated only` means deterministic tests pass but native acceptance is incomplete; `Blocked` means a named environmental prerequisite is missing; `Failed` means the implementation behaved incorrectly; and `Not implemented` means the product must not imply the feature exists.

Agent tasks are also part of the acceptance harness. When a real Clicky agent reports friction or a code risk, preserve its event trail, turn the finding into a regression test, and rerun the same scenario after the fix. A task that merely produces plausible prose is not a pass; its commands, approvals, artifacts, stop/retry behavior, and visible result must agree.

## Release gate and execution order

The highest-value gate is the path from speech to useful work. Run literal dictation first, then screen-aware composition, explicit and automatic routing, durable Codex agents, and finally cursor/spatial behavior. Privacy, permission recovery, and a responsive escape hatch are P0 because a polished feature is still unsafe if it writes into the wrong field, leaks private content, or freezes the user's cursor.

```text
P0 trust + escape hatch
        |
        v
P1 literal dictation --> P1 screen-aware composition --> P1 router
                                                        |
                                                        v
                                               P1 Codex agents
                                                        |
                                                        v
                                      P2 cursor + spatial interaction
                                                        |
                                                        v
                                       P2 displays + P3 resilience
```

## Current release assessment

The 42-case matrix currently contains 11 verified cases, 17 partial cases with native evidence, 8 automated or code-audited cases, 4 cases ready for native acceptance, 1 case needing a native voice retest, and 1 not-run case. There are no known failed or not-implemented cases inside the pre-skills milestone.

The strongest current slice is the Codex agent runtime and its redesigned line-based HUD: real subscription-backed tasks, parallelism, approvals, structured input, stop, same-thread follow-up, history, app-server reconnect, durable tokens, and the hang regression have all been exercised in the native build. A three-agent timed run preserved independent interim state and delivered every terminal result and token, with bounded memory; its 25.9% mean and 46.4% peak Clicky CPU confirm that streaming presentation performance is still a release gate rather than a solved claim. Spoken answers can resume the exact structured-input request, while TTS now emits only a generic attention cue instead of reading internal prompts or command details. The child runtime inherits developer tools, drains terminal output in order, sanitizes bounded diagnostics, and projects disconnects into recoverable task state. The installed authenticated app-server now passes live handshake, safe ephemeral-thread, and local-image companion tests, confirming the shared central runtime outside mocks. The signed-out recovery surface follows the app-server-managed ChatGPT login lifecycle but still needs destructive native acceptance on a signed-out account. Literal dictation and spoken routing have substantial implementation and deterministic coverage; a live failed voice attempt was isolated to the pre-creation route because the same visible composer immediately created and completed a task, and natural punctuation-free agent triggers now have explicit regression coverage. Their complete physical cross-app matrix remains. Companion vision and screen-aware composition use subscription-backed response-only app-server threads with local screen images and read-only sandboxes. Cursor pointing, static model-authored annotations, bounded user-trace grounding, and TARGET/HOVER walkthroughs are wired and tested, while live model-authored spatial alignment remains a native release gate. Full-screen attention delivery is now verified: a persistent completed-task token reopened the correct detail in the current Xcode Space after the panel reorder fix. Accessibility semantics now cover the primary navigation and agent controls, while focus retention, live state announcements, and human VoiceOver acceptance remain partial. Long-horizon autonomy now completes the requested artifact turn, but real-browser follow-up, streaming CPU, and full accessibility acceptance remain partial. Experimental realtime audio, computer-use automation, local memory/skill management, and external integrations remain deferred rather than implemented parity.
