# HeyClicky parity manual QA

This is the acceptance plan for Clicky's clean-room HeyClicky parity work. It complements automated tests by requiring a person to observe the real macOS behavior in Xcode-run builds. Every run records the app commit, macOS version, display layout, Codex version, transcription provider, permission state, and whether the behavior was compared with the installed HeyClicky reference.

The status vocabulary is intentionally strict: `Verified` means the behavior was observed in the native app; `Automated only` means deterministic tests pass but native acceptance is incomplete; `Blocked` means a named environmental prerequisite is missing; `Failed` means the implementation behaved incorrectly; and `Not implemented` means the product must not imply the feature exists.

Agent tasks are also part of the acceptance harness. When a real Clicky agent reports friction or a code risk, preserve its event trail, turn the finding into a regression test, and rerun the same scenario after the fix. A task that merely produces plausible prose is not a pass; its commands, approvals, artifacts, stop/retry behavior, and visible result must agree.

## Release gate and execution order

The highest-value gate is the path from speech to useful work. Run literal dictation first, then screen-aware composition, explicit and automatic routing, durable Codex agents, and finally cursor/spatial behavior. Privacy, permission recovery, and a responsive escape hatch are P0 because a polished feature is still unsafe if it writes into the wrong field, leaks private content, or freezes the user's cursor.

```text
P0 trust + escape hatch
        |
        v
P1 literal dictation --> P1 screen-aware composition --> P1 router
                                                        |
                                                        v
                                               P1 Codex agents
                                                        |
                                                        v
                                      P2 cursor + spatial interaction
                                                        |
                                                        v
                                       P2 displays + P3 resilience
```

## Current release assessment

The strongest current slice is the Codex agent runtime and its redesigned line-based HUD: real subscription-backed tasks, parallelism, approvals, stop, same-thread follow-up, history, app-server reconnect, durable tokens, and the hang regression have all been exercised in the native build. The child runtime now inherits developer tools, drains terminal output in order, sanitizes bounded diagnostics, and projects disconnects into recoverable task state. The signed-out recovery surface now follows the app-server-managed ChatGPT login lifecycle, including completion identity and best-effort cancellation, but still needs destructive native acceptance on a signed-out account. Ordinary task errors are dismissible and no longer masquerade as transport failures. Literal and screen-aware dictation have substantial implementation and deterministic test coverage, all required TCC grants are active, and physical shortcut acceptance is the remaining gate. Spoken trigger phrases and automatic routing are not implemented. Cursor pointing remains a reusable baseline with repaired lifecycle ownership, while static model annotations, user-drawn spatial grounding, and interactive walkthroughs remain later parity work.
